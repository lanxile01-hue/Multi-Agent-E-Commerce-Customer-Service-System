# 08 · 运行、配置与部署

## 1. 环境与安装

- Python **3.11+**（Dockerfile 用 3.12-slim）
- 依赖见 `requirements.txt`（LangGraph、OpenAI SDK、Pydantic、tiktoken、httpx 等）

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows；macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # 填自己的 key，切勿把真实密钥写回 .env.example
python -m app.scripts.build_kb_index   # 首次构建知识库索引（向量 + BM25）
```

## 2. 配置项（`.env`）

### LLM
| 变量 | 说明 |
|---|---|
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` | 任意 OpenAI 兼容接口（OpenAI / DeepSeek / 中转均可） |
| `MODEL_NAME` / `TEMPERATURE` | 主模型与采样温度 |

### Embedding（可与 LLM 分离）
| 变量 | 说明 |
|---|---|
| `EMBEDDING_API_BASE` / `EMBEDDING_API_KEY` / `EMBEDDING_MODEL` | 留空则回退到 LLM 的 `OPENAI_*`；支持自建服务（如 bge-m3）或云服务（如 DashScope） |

### RAG
| 变量 | 说明 |
|---|---|
| `KB_DIR` | 知识库文档目录（默认 `app/agent/rag/knowledge`） |
| `RAG_BACKEND` | `numpy` / `chroma` |
| `KB_INDEX_PATH` / `BM25_INDEX_PATH` | 两份索引的落盘位置 |
| `CHROMA_PERSIST_DIR` / `CHROMA_COLLECTION` | Chroma 后端专用 |
| `ADAPTIVE_RAG_ENABLED` | 是否启用 Adaptive-RAG（Rewrite + 策略路由 + 双路召回 + RRF + Rerank） |
| `COHERE_API_KEY` | 可选，填写后启用 Cohere 精排 |
| `CHUNK_MAX_SIZE` / `CHUNK_OVERLAP` | 通用分块配置位（真正生效的是 `chunker.py` 的 `MAX_CHUNK_CHARS = 250`） |

### Supervisor / Checkpoint / 安全
| 变量 | 说明 |
|---|---|
| `SUPERVISOR_ENABLED` | 主线架构开关（默认 `true`） |
| `MULTI_AGENT_ENABLED` / `LANGGRAPH_ENABLED` | 旧版编排器 / 单 Agent 状态机开关 |
| `CHECKPOINT_ENABLED` / `CHECKPOINT_BACKEND` / `CHECKPOINT_PATH` | `memory` / `sqlite` / `postgres` / `auto` |
| `HUMAN_CONFIRMATION_ENABLED` | 敏感操作是否 interrupt 等确认（默认 `true`） |
| `SUBGRAPH_MAX_STEPS` / `TOOL_TIMEOUT` | 子图步数上限 / 工具超时 |
| `REFUND_STORE_PATH` | 退款幂等与审计 SQLite 路径 |
| `GUARDRAILS_ENABLED` | 幻觉检测 + 自纠错开关 |

### 会话 / 记忆 / 技能 / MCP
| 变量 | 说明 |
|---|---|
| `MEMORY_ENABLED` / `MEMORY_DIR` / `MEMORY_USER_ID` / `MAX_LTM_FACTS` | 长期记忆开关、目录、默认用户与事实上限 |
| `SKILLS_ENABLED` / `SKILLS_DIR` | 技能目录（`SKILL.md`） |
| `MCP_ENABLED` / `MCP_SERVER_URL` | 是否合并 MCP 工具，以及 MCP Server 地址 |
| `TOKEN_BUDGET` / `COMPRESSION_*` | Token 预算与三层压缩水位 |

### 评估 / 可观测性
| 变量 | 说明 |
|---|---|
| `EVAL_DATASET_PATH` / `EVAL_USE_JUDGE` / `EVAL_PASS_THRESHOLD` | 黄金集路径、是否启用 LLM judge、通过阈值 |
| `LANGCHAIN_TRACING_V2` / `LANGCHAIN_API_KEY` / `LANGCHAIN_PROJECT` | 可选，接入 LangSmith |

> `MILVUS_*`、`PROMETHEUS_*` 目前只是配置位，代码里尚未接入。

## 3. 命令速查

## 4. 服务化接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/chat` | body：`{"user_input": "...", "thread_id": "..."}` |
| `POST` | `/chat/{thread_id}/resume` | body：`{"decision": "确认"}`，用于退款等待确认后的恢复 |
| `POST` | `/chat/{thread_id}/reset` | 重置指定 thread |
| `GET` | `/chat/{thread_id}/state` | 返回脱敏状态（`interrupted` / `has_checkpoint`） |
| `GET` | `/health` | 健康检查 |

限流：进程内固定窗口 60 次/60 秒（按客户端 IP）；同一 thread 并发请求返回 **409**。
网页调试台（`app/web/index.html`）支持对话、查看引用、查看/重置会话。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 终端里 emoji 显示成 `?` 或报 `UnicodeEncodeError` | 代码已把编码错误降级为替换字符；想要正常显示可先执行 `chcp 65001` 或设置 `PYTHONIOENCODING=utf-8` |
| 检索报"知识库初始化失败 / 索引不存在" | 先跑一次 `python -m app.scripts.build_kb_index` |
| Embedding 调用失败 | 检查 `EMBEDDING_API_BASE` 是否可达（自建服务常见）、key 是否有效；也可换成云厂商 embedding |
| 退款没有执行 | 这是设计行为：需要先回复「确认」；模糊输入会被当成「重新说明」，不会执行 |
| 想从全新状态开始演示 | 删除 `app/sessions/` 下的 `session.json`、`refunds.db`、`memory/*.json`，或调用 `agent.reset()` |
| 测试全部报权限错误（Windows） | 属环境问题：pytest 需要写系统临时目录，换有权限的终端或指定 `--basetemp` |

## 7. 已知边界与技术债

- API 层是**演示级**实现：没有鉴权、没有多租户、限流只在进程内，生产需要替换为 JWT/OIDC + 网关限流。
- Checkpoint 默认 `memory` 后端，生产应切 `sqlite` / `postgres`。
- 退款存储是本地 SQLite，多实例部署需换共享存储 + 分布式锁。
- 压缩链路存在两套口径（`compressor.py` 完整三级 vs Supervisor 的按条数压缩），应统一。
- 检索分块参数存在"配置位（800/100）与代码常量（250）不一致"的问题。
- `compensation` / `complaint_escalation` 等高风险工具尚未实现，仅在风险分级表中预留。
- 忠实度评测依赖 LLM judge，推理模型下需要足够的 token 预算，否则指标失真。
