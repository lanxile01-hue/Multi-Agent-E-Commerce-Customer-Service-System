# 05 · 状态恢复、压缩与记忆

对应代码：`app/multi_agent/checkpoint.py`、`app/agent/storage.py`、
`app/agent/compressor.py`、`app/agent/memory/`、`app/agent/skills/`

## 1. 三层状态，别混用

| 层 | 存什么 | 生命周期 | 位置 |
|---|---|---|---|
| 会话文件 | 对话历史、摘要、短期记忆 | 跨进程（JSON 落盘） | `SESSION_PATH`，默认 `app/sessions/session.json` |
| Checkpoint | 图执行节点、工具结果、等待确认状态 | 取决于后端 | `CHECKPOINT_PATH` |
| 长期记忆 | 用户偏好、身份、历史问题等事实 | 跨会话按用户持久化 | `MEMORY_DIR/{user_id}.json` |

## 2. Checkpoint 后端

| 后端 | 语义 | 适用 |
|---|---|---|
| `memory`（默认） | `MemorySaver`，仅进程内，重启即丢，**不能跨进程恢复** | 开发 / 单次会话 |
| `sqlite` | `SqliteSaver`，写入 `CHECKPOINT_PATH`，interrupt 状态随 checkpoint 落盘 | 单机持久化、重启续跑 |
| `postgres` | `PostgresSaver`（需 `langgraph-checkpoint-postgres`，未安装时安全回退） | 多实例共享 |
| `auto` | 依次尝试 sqlite → postgres → memory | 部署时省心 |

协作约定（避免重复嵌套）：

- **只有父图** `compile(checkpointer=...)`；三个子图作为父图节点运行，不单独携带 checkpointer；
- 子图内的 `interrupt()` 冒泡到父图，由父图整体暂停 / 恢复；
- `thread_id` 由 `session_path + user_id` 稳定派生，也可在 `chat()` / `resume()` 显式传入。

## 3. 中断与恢复

```python
agent.chat("我要退款订单 ORD-20240115-001", thread_id="user-123")   # 返回确认提示
agent.chat("确认", thread_id="user-123")                            # 恢复执行
agent.resume("user-123", "确认")                                    # 等价的显式恢复
agent.reset(thread_id="user-123")                                   # 清理该 thread 的 checkpoint 与 interrupt
```

是否处于"等待确认"，判断依据是 Checkpoint snapshot 的 `next` 字段（不用内存字典），
所以用 sqlite 后端时**进程重启也能接着确认**。

## 4. 上下文压缩

主线压缩在 `app/multi_agent/supervisor.py::_maybe_compress`：
历史条数超过 `history_threshold`（默认 10）时，保留最近 `history_keep_recent`（默认 3）条原文，
其余交给 `app/agent/summarizer.py::summarize()` 生成摘要（工具消息做安全回退），
避免上下文无限增长、也避免"切在工具消息中间"导致格式错误。

仓库里另有一份更完整的**三级渐进式压缩**实现 `app/agent/compressor.py`
（`TOKEN_BUDGET` 默认 128000，按 50% / 70% / 85% 三档分别做轻量截断、中度压缩、LLM 增量摘要）。
它当前**未接入主线**——两条口径并存属于待收口的技术债：理想做法是统一到 `compressor.py`，
让压缩按 token 预算驱动，而不是按历史条数驱动。

## 5. 记忆

`app/agent/memory/manager.py`：

- **短期记忆（STM）**：会话内提取的事实，随会话文件持久化，`reset` 清空；
- **长期记忆（LTM）**：按 `user_id` 落 `MEMORY_DIR/{user_id}.json`，存偏好 / 身份 / 行为类事实，
  上限 `MAX_LTM_FACTS`（默认 50）；提供 `recall_user_memory` 工具供模型主动查询；
- 开关：`MEMORY_ENABLED`；**评估沙箱里会强制关闭**，避免历史记忆污染评分。

## 6. 技能（Skill）

`app/agent/skills/loader.py` 扫描 `SKILLS_DIR` 下的 `SKILL.md`（YAML frontmatter + Markdown 指令），
常驻上下文的只有 `name + description`，模型需要时通过 `load_skill` 加载完整指令体（渐进式披露）。

当前内置四个技能（详见 [09-Skill 可复用能力模块](09-Skill-可复用能力模块.md)）：

| 技能 | 场景 |
|---|---|
| `process-return` | 退货退款处理：确认订单 → 校验资格 → 退款 → 告知进度 |
| `track-order` | 订单物流跟踪：查单 → 查物流 → 综合建议 |
| `product-recommend` | 商品推荐：了解需求 → 查偏好 → 搜索 → 推荐 |
| `complaint-escalation` | 投诉受理与升级：安抚 → 核实举证 → 检索规则 → 分级处理（L1 自助 / L2 转人工） |
