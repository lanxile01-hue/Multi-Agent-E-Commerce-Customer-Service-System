# 02 · 多智能体编排与工具隔离

对应代码：`app/multi_agent/{supervisor,subgraphs,router,agents,state,structured}.py`

## 1. 路由：怎么决定交给谁

`Router.route()`（`app/multi_agent/router.py`）是两级结构：

1. **关键词预检**：命中投诉强信号词（`投诉 / 举报 / 差评 / 假货 / 12315 / 维权 / 赔偿 / 道歉 ...`）
   直接判 `complaint`，省掉一次 LLM 调用；
2. **LLM 分类**：把用户消息交给分类 Prompt（`app/prompts/agents.py::ROUTER_PROMPT`），
   要求只输出 `presale / postsale / complaint` 三个词之一。

兜底：模型输出无法识别时，中文标签会经 `CHINESE_MAP` 归一化；仍然无法判断则落到
`DEFAULT_AGENT = "postsale"`（售后是覆盖面最广的域）。

## 2. 子图内部：七个节点

三个子图结构完全相同（`app/multi_agent/subgraphs.py`），差异只有领域 Prompt 与工具白名单：

| 顺序 | 节点 | 职责 |
|---|---|---|
| 1 | `agent_enter` | 重置子图临时字段，注入领域 Prompt、工具清单、记忆与技能目录 |
| 2 | `agent_reason` | 任务规划：判断"还缺什么信息、下一步做什么"（`model_calls += 1`） |
| 3 | `agent_decide_tool` | 决定 `call_tools` 还是 `respond`；工具参数做 schema 校验 |
| 4 | `human_confirmation` | 命中高风险工具时 `interrupt()` 暂停父图，等待用户确认（可关闭） |
| 5 | `execute_tools` | 并发执行工具（线程池 + 超时），按 `retryable` 决定是否重试 |
| 6 | `evaluate_result` | 判断信息是否足够；不足则回到 `agent_reason` 继续规划 |
| 7 | `generate_response` | 生成最终回复并收敛成结构化输出 |

循环上限由 `SUBGRAPH_MAX_STEPS` 控制，避免模型"想不完"导致死循环。

## 3. 工具隔离：每个子 Agent 看得到什么

`app/multi_agent/agents.py::AGENT_CONFIGS` 定义白名单，`ToolManager(allowed_tools=...)`
在**工具定义层**就过滤掉越权工具——模型看不到，也就不会调用：

| 子 Agent | 可见工具 |
|---|---|
| `presale`（售前） | `query_product`、`search_knowledge`、`list_user_orders`、`load_skill` |
| `postsale`（售后） | `query_order`、`query_logistics`、`apply_refund`、`list_user_orders`、`search_knowledge`、`load_skill` |
| `complaint`（投诉） | `query_order`、`search_knowledge`、`load_skill` |

注意 `apply_refund` **只出现在售后域**：售前和投诉子图根本拿不到退款工具。

## 4. 工具清单

本地注册表（`tools/registry.py`）共 8 个工具：

`query_order`、`query_logistics`、`query_product`、`list_user_orders`、
`search_knowledge`、`apply_refund`、`recall_user_memory`、`load_skill`

MCP Server（`mcp_server/server.py`，Streamable HTTP）另暴露 5 个：
`query_order`、`query_product`、`query_logistics`、`apply_refund`、`search_knowledge`。
`MCP_ENABLED=true` 时由 `ToolManager` 合并进工具表，schema 经 `app/mcp_client/converter.py` 转换。

## 5. 执行策略

| 关注点 | 实现 |
|---|---|
| 参数校验 | `validate_tool_arguments()`：调用前比对 schema，参数错误直接拒绝，不消耗一次工具调用 |
| 超时 | `TOOL_TIMEOUT`（默认 30s），线程池 `Future.result(timeout)` |
| 重试 | 只有标记为 `retryable` 的错误才重试，采用指数退避 `0.1 * 2**attempt` |
| 禁止重试 | 非幂等写操作（`apply_refund`）**永不自动重试**，避免重复退款 |
| 错误分流 | `tools/errors.py` 统一错误类型，供规划节点换策略 |

## 6. 结构化输出

`app/multi_agent/structured.py` 把子图结果收敛成 `CustomerServiceResponse`：

1. 模型支持 `response_format` / `beta.parse` 时**直接产出结构化对象**；
2. 不支持的模型走确定性 fallback：文本回复 + 字段映射（`AGENT_TO_INTENT`），
   **不再二次调用 LLM 提取**；
3. 任何路径都过 Pydantic 校验，缺字段给安全默认值；
4. 内部思考、工具参数、原始工具返回**绝不返回给用户**，只保留 `citations` 摘要。

## 7. 什么情况建议转人工

`AGENT_REQUIRES_HUMAN` 给出默认倾向（投诉默认倾向转人工，售前/售后默认不转），
再由 `validate_response` 节点结合回复内容与置信度最终判定，写入 `requires_human`。
CLI 每条回复底部都会打印 `[意图 | 置信度 | 转人工]`。
