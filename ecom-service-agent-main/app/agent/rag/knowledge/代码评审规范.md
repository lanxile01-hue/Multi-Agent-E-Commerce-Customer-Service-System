# 代码评审规范

## 一、评审目标

代码评审重点关注正确性、安全性、可维护性和可观测性。评审意见需要指向具体代码和风险，不以个人风格偏好替代工程判断。

## 二、提交前检查

提交人应说明背景、改动范围、兼容性影响和验证方式。涉及数据库、权限、外部接口或配置变更时，必须补充回滚方案和灰度计划。

## 三、高风险改动

涉及鉴权、支付、个人信息、删除数据和生产配置的改动，至少需要两名评审人。敏感操作必须具备幂等、审计日志和失败恢复路径。

## 四、评审结论

阻塞问题修复后才能合并；非阻塞建议可以转为后续工单。评审人不得直接修改提交人的代码后绕过确认流程。
