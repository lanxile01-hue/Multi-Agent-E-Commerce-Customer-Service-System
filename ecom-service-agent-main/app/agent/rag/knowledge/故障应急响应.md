# 故障应急响应

## 一、故障分级

P0 表示核心业务全面不可用或存在重大数据/安全风险；P1 表示核心功能明显受损；P2 表示局部功能异常但有可用替代路径。无法判断时按较高等级响应。

## 二、响应步骤

先确认影响范围和时间线，再建立事件记录，指定事件负责人、技术负责人和沟通负责人。处理过程中优先止损和恢复服务，避免未经评估的扩大性操作。

## 三、证据留存

保留相关日志、Trace、配置版本、发布记录和操作命令。涉及个人信息时只保留脱敏后的样本，不在群聊中传播原始敏感数据。

## 四、复盘要求

故障恢复后两个工作日内完成复盘，内容包括影响、时间线、根因、临时措施、长期改进项和负责人。复盘重点是改进系统，不针对个人进行归责。
