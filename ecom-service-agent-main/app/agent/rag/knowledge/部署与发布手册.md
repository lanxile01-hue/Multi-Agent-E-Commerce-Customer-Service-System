# 部署与发布手册

## 一、发布前检查

确认构建产物版本、数据库迁移脚本、配置变更和依赖镜像已经完成评审。发布前必须在预发布环境执行健康检查、核心接口检查和回滚演练。

## 二、灰度发布

默认先向小比例实例发布，观察错误率、延迟、资源使用率和业务关键指标。灰度期间禁止同时进行无关的配置和数据库结构变更。

## 三、回滚条件

出现持续错误率升高、关键接口不可用、数据一致性风险或安全事件时立即停止扩大流量。应用回滚必须记录版本、操作者、原因和开始/结束时间。

## 四、发布后确认

发布完成后检查健康接口、日志采集、告警状态和关键链路。确认稳定后关闭发布工单；如果存在遗留告警，必须在工单中说明责任人和处理计划。
